# Long-Task Mechanism Admission

Read this reference before changing Long-Task Schema, Source/Contract authoring, Claims/Assertions, Evidence Kernel, Compact Carrier, Preflight/Compile/verify/Final Gate, Stop/close/resume/status, Authority Revision, workspace scope, risk, performance, Skill, Hook, profile, distribution or recovery behavior.

## Controlling purpose and inputs

Read the Long-Task Controlling Objective, Authority Scope And Trusted Results, Mechanism Admission Rule and Anti-Degradation Assurance in `PROJECT_SPEC.md`; `project_context/areas/harness-package/decision-rationale/long-task-workflow.md`, the owning workflow contract, implementation-index and verification Context; and the actual code/proof owners. Confirm that current-implementation Context still names the real runtime path before designing a change.

Source carries complete declared meaning, Contract carries machine bindings and obligations, Active Authority protects the locked identity, and the sole Final Gate recompiles and reruns declared project Checks on one current candidate. Progress, delegated reports, historical results, prose inspection and Receipts never create acceptance.

## Lexicographic admission

Evaluate changes in this order:

1. prove a declared-purpose validity floor inside the named threat model and TCB: every frozen critical counterexample is rejected, every independently grounded correct control passes, each critical sentinel fails at its claimed semantic owner/boundary, and no known critical false acceptance remains open;
2. prove `Coverage_new ⊇ Coverage_valid_baseline` and `FalseNegative_new ⊆ FalseNegative_valid_baseline`; invalid old behavior is defect rather than protected baseline, and Coverage is demonstrably rejected erroneous completion paths rather than test/Fact/tag counts;
3. prove Authority, fail-closed behavior and complete current-final-snapshot verification remain non-bypassable;
4. preserve semantic granularity and the explicit admitted Observer/Oracle/Inspector/runtime trust boundary;
5. only then compare total authoring, runtime, state, recovery, maintenance, test, process, adoption and migration cost;
6. positive net ROI admits consideration, never automatic adoption.

Cost reduction cannot compensate for weakened drift interception. If non-degradation cannot be established, leave the formal acceptance path unchanged and isolate any experiment outside it. With equivalent cost, prefer stronger purpose fulfillment; with equivalent effect, prefer lower total cost. Use measured data when available; otherwise use rigorous causal argument plus a small bounded validation and involve the user/project owner when a genuine product choice remains.

For every added, removed or strengthened mechanism, identify the exact false-completion path, invariant, independently grounded positive/negative controls, expected failure owner/localization, must-allow controls, proof/check, overlap, deletion reopening risk, fail-closed behavior and total incremental benefit/cost. Freeze a reproducible critical incident before repair and downgrade the affected capability wording until its required regression and replay close. A sentinel rationale, prose audit, green aggregate or fresh-Agent run cannot establish behavior its controls do not prove. Implement runtime/invariant changes in the mechanism owner; do not disguise them as documentation or test-only changes. Add no Mechanism Matrix, Receipt, second registry or state merely to record this reasoning.

For Observer/TCB changes, classify trust by capability and the complete observation chain, never file age. Preserve distinct expected, actual, comparison/result-identity and verdict owners. A nonce may strengthen Harness-internal execution identity but is neither exposed to the product nor a semantic trust root. A project runner's `value_sha256`, `passed` or `verdict` cannot alone close a material Claim; use a package-owned admitted extractor/comparator, a directly invoked digest/version/capability-frozen executable, or target-blocking External Confirmation. Keep the first admitted artifact/locator set bounded, with explicit media/schema/version, normalization/tolerance/mask, containment/no-follow, resource and protected-value rules. Do not build a universal UI observer or a second Fact taxonomy.

The admitted-observation/runtime-TCB revision is stricter than a sound-project-verifier premise. Compile each machine Claim or Fact × required-method obligation to an ephemeral package-owned observation-authority projection that selects exactly one of bounded static JSON exact observation, bounded direct-process JSON exact observation or the existing blocking External Confirmation. This projection is derived from Source/Contract and existing owners; it is not a public Contract Authority, schema registry, persistent state or second completion result. An unrecognized/custom Oracle, unsupported proof surface, missing target-family match or unavailable Harness-owned actual channel is never a legacy fallthrough: machine authoring must fail with an actionable diagnostic until the Contract explicitly uses External Confirmation.

Static exact observation is limited to plain UTF-8 JSON implementation/configuration structure that already exists in the candidate's pre-run snapshot manifest. The Harness must bind its pre-run path, bytes and file identity, reject creation, modification, replacement, link switching or identity/digest drift by the runner, and reject Source/Context/Contract/expected resources plus evidence, verifier output, status, report, comparison, Receipt and other proof-only carriers. A static carrier proves only its current structure; a Binding or `input_path` cannot promote it to runtime consumption, interaction, target liveness or rendered behavior.

Runtime exact observation is initially limited to a Source-backed `process` target whose role is product and whose `project_binary` runner is the declared direct root invocation—target plus complete `root_argv`—for the root journey with read-only or test-sandbox effect. Every required target must have one canonical Source technical-obligation projection covering key, role, runtime family, root, complete argv and capabilities. The root, argv-referenced repository files and required product modules/configuration must be owned by the production path/Binding; runner, verification-input, fixture or `input_paths` membership is not product authority. Compile derives one declaration-stable internal `CompiledProcessRuntimeClosure` containing only exact Source-backed root/argv paths and exact Claim/Counterfactual production carriers. It never expands every `input_path` or manifest/glob sibling. Exact planned members may be absent at Preflight/Compile but must exist at Final Gate; an unbound repository-file argv token fails Compile, while URL/absolute/parent-escape/non-file labels are outside the bounded token rule rather than inputs to a dependency parser. One role check rejects every closure member overlapping Source/Contract/Context/expected authority, verification input, evidence/status/report/comparison/Receipt/Long-Task workdir, `expected_output_paths`, `artifact_globs` or historical evidence/session. Harness copies only the compiled closure into an OS-temporary snapshot, directly owns spawn/process-tree cleanup and captures one bounded `ty-context-product-observation-v1` envelope from stdout. Compatible Cross-Check and implicit-preserved Facts share the Raw Execution/envelope but retain independent obligation/comparison identities. The child receives no observation-output, challenge or protocol environment variable. Harness-derived attestation binds the compiled closure identity in addition to executable/root/argv, PID, times, exit, candidate and observation digest. Subtraction review retains prepare-all mutation watching plus per-file pre/post identity/hash and bounded timeout/descendant cleanup because the frozen transient/persistent/descendant/timeout controls fail without them; these remain explicit Node/host-OS TCB, not hostile-host proof. Currently only exact/presence Actuals and host `target_runtime` are package-derived. `interaction_trace`, `state_delta`, `design_conformance` and every capability without a complete package derivation remain blocking External Confirmation. Browser, Native, device, layout, pixel, accessibility, motion, protected-value, tolerance/mask, custom locator/Oracle and indirect-wrapper observation likewise remain External Confirmation until a separately admitted package adapter exists. Keep public check-result v3; no v4, dependency-language parser or hostile-host sandbox is introduced.

Every admitted exact path—V1 ground, V2 symbolic, non-UI Semantic Fact, static JSON and direct process—uses the one Harness exact evaluator and Harness-recomputed result identity. Submitted actual digests may be checked for agreement, but submitted `passed`, `verdict`, `target_runtime`, `interaction_trace`, `state_delta`, aggregate Booleans or session IDs are compatibility diagnostics, never Authority. A disagreement fails closed. A claim-bearing Counterfactual may not skip when baseline and mutated admitted-observation sets are empty: static causality is limited to the changed structure Fact itself, while runtime reachability requires Harness mutation of a carrier in the compiled production set, another direct run of the same Source-backed root and a package-observed actual change. Baseline/mutated closure identities and obligation universes are equal; affected, preserved, allowed-fan-out and liveness rules remain enforced, and any Authority/verification/evidence member fails closed.

Until the frozen end-to-end attack/control suite, Trust/full/package checks, black-box Final Gate, independent capability audit and a qualified real-process-workload ROI comparison all close, describe the mechanism at most as Level 3—protected against the declared known counterexamples. Deterministic attacks establish known-path rejection, not arbitrary observer soundness; an implementation Agent cannot self-promote the claim to Level 4.

## Protected purpose and implementation freedom

The protected causal chain has two jointly necessary responsibilities: complete requirement/architecture meaning capture and fail-closed current-snapshot proof before terminal acceptance. Weakening, reinterpreting or replacing the purpose, key logic, either responsibility or its theorem boundary requires an explicit project-owner design-purpose decision plus old/new implication, coverage/false-negative impact, compatibility/migration and replacement proof. Agent inference, coordinated docs/code/test edits or cost alone cannot authorize it.

Semantic Granularity, Semantic Fidelity and Delegated-Choice Validity may refine the existing key logic, explicit boundary and first meaning-capture responsibility; they are not replacement responsibilities or new theorem premises. The second responsibility remains Source/Contract continuity, Authority, observers, repair localization, freshness and the sole current-snapshot Final Gate. Upstream DRA Provider history/checkpoints/audits can improve Source quality but never become evidence that this Final Gate proved historical Provider execution.

`F = Implementation Freedom Boundary` is adjacent protected anti-process-bloat policy, not a third theorem premise. Within Source/Contract, architecture, safety, forbidden-shortcut, irreversible-effect and external-action boundaries, the current Goal owns implementation order, methods, feedback cadence and optional platform-native one/multi-agent execution. Harness creates no development-method Gate, per-edit mandate, allocation/retry/recovery scheduler, delegation proof or persistent dispatch state. A new development-path constraint requires the same owner decision, a distinct uncovered risk that Final Gate or a lighter project check cannot cover, non-degradation and positive net ROI.

The optional Codex worker is a fixed, stateless, non-Authority host affordance. It cannot route the parent model, persist a model decision, schedule work, own lifecycle/proof/acceptance or affect the fallback acceptance path. The first Authority Lock terminal-turn checkpoint is also a host affordance: Harness emits the static boundary, observes no model change and stores no acknowledgement/route state. Static profile/Hook changes need executable validation, safe distribution and behavior tests, but no new control plane.

## Engineering-quality carrier

Architecture Deliberation remains universal and risk-proportional. Correctness/invariants and maintainability/changeability always receive a preservation judgment; other quality families activate only when material. Default Contract Conformance and Long-Task Final Gate are mutually exclusive carriers on one current candidate. Long-Task expresses only declared, falsifiable, project-check-bound quality invariants through existing Source-backed obligations/constraints/forbidden shortcuts, owners/paths/Bindings, executable Checks and separate Assertions where functional behavior could pass independently.

Do not add a quality artifact, matrix, Source aspect, Claim/risk kind, Contract field, second Authority/Gate/state or generic analyzer. Unsupported modularity metrics remain `null`/`n/a` and cannot influence risk. A performance claim needs workload, metric, baseline/budget, environment, comparator/tolerance and a project-owned measurement; static shape is not runtime proof.

Any design-purpose/rationale update stays causally complete: problem/purpose, inputs/transformation, unique authority and non-ownership, downstream consumption/proof, fail-closed limits, costs/alternatives and every indexed surface must agree.
