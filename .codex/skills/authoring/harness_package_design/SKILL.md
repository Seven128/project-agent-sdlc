# Package maintenance

Tiny Context preserves durable project facts and one short development contract. Read relevant Context and preserve user-authorized scope. Existing user requirements and security constraints survive tool retirement.

Edit the actual canonical owner, then synchronize package and installed generated copies through source-mappings.yaml. Keep public guidance English-complete and repository-only authoring instructions out of consumer assets.

Protect user files and mixed configuration. Explicit upgrades own semantic migration; sync only refreshes supported managed assets. Preserve path safety, concurrent-change detection and recoverability. Never equate a multi-file replacement with filesystem atomicity.

Run affected checks while working, then current-candidate regression, source parity/idempotence and actual tarball consumer checks for distribution changes. Report what was checked and material limitations. Do not preserve retired machine proof, role workflow or ROI governance as a requirement for maintenance.
