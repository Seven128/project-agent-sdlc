# Tiny Context product design

Tiny Context preserves project-specific information and supplies a short automatically applicable development contract. It helps an agent recover intent and maintain files; it does not prescribe an entire engineering workflow.

## Durable memory

Keep difficult-to-recover goals, non-goals, responsibilities, dependency and lifecycle boundaries, user decisions, rationale, operational entrypoints and references. Code owns exact implementation. Existing design sources remain useful without a formal adoption state machine. No task ledger, fixed headings or claims of fact correctness from structural validation.

Default reading starts with global.md and project-declared selections. Catalog owns selection and diagnostics; direct file reading works without CLI/network installation. Areas and workspace organization remain optional and sparse. Relevant dependencies expand reading, never authorization to edit.

## Development contract

Understand real inputs, respect authorization and project constraints, implement through appropriate existing owners, inspect actual results, test in proportion to risk and project requirements, repair failures, refresh affected evidence after changes, maintain changed durable facts and report results honestly. No mandatory plans, design handoffs, model checkpoints, delegation or intermediate reports.

## Maintenance and migration

New installation is minimal. Sync updates managed instructions without semantic migration. Explicit schema-5 upgrade retires old capabilities while protecting user modifications, histories, worktrees and active information dependencies. Existing unfinished Context transactions must be resolved through a compatible old recovery tool before switching. Automatic migration preserves exact default body path sets, including legacy graph behavior. Live old requirements requiring removed decoding must be extracted/replaced with provenance before information migration can be called complete.

Validation reports supported structural/configuration/path checks only. Ordinary prose links, historical test statements, headings and file length are not proof or blockers. Context transactions keep journals, mutual exclusion, byte/identity comparisons and safe recovery; this is file safety rather than task orchestration.

## Historical boundary

Earlier releases offered Long-Task, DSA/DRA, exact facts, formal handoffs, machine completion and proof/cost governance. The project owner explicitly retired those product promises. Historical artifacts remain ordinary readable material; their old execution rules are not current requirements. Compatibility remains bounded to retirement diagnostics and migration, never a hidden old runtime.

## Verification and stopping

Use ordinary logic, maintenance, key integration/migration and actual tarball consumer tests. Preserve safety checks shared with retired features; remove exclusive tests rather than skip or fake them. Report actual execution and unverified scope. No claim of zero model omission, universal quality or measured speed improvement without appropriate observations. Stop expanding machinery once the approved behavior is implemented and checked.
