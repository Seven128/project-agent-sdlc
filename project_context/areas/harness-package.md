# Package ownership

This repository maintains project-tiny-context-harness and the ty-context CLI. Its supported product is Minimal Context plus a short development contract, with safe maintenance tools.

Retain init, sync, explicit upgrade, doctor, validate-context, Context list/inspect/create/register/move/transaction, package source sync/check and useful exports. Retire workflow profiles, Long-Task/composite/delivery commands, design-authority/resource commands, route rankings and package source-line gates. Retired command diagnostics must fail rather than return weakened success.

New projects need only startup instructions, Harness config, project_context/global.md and context.toml. Architecture, Areas, verification files and design documents are optional. No fixed Context headings, truth-by-keyword checks or task progress requirements. Defaults comprise global and explicit project selections; dependencies expand reads without expanding edit authority.

Schema-4 consumers require explicit schema-5 upgrade. Preserve exact default body paths, user modifications, mixed files, history and live unique requirements. Block before switching when an old Context journal cannot be safely resolved or a live dependency remains unusable. Separate mechanical asset success from nonmanaged prose review; historical mentions alone do not block. Bound adapters to documented formats and pin compatible old recovery versions.

Package guidance is English-complete. Edit canonical source and sync derived assets, prove idempotence and consume the actual tarball. Retain file safety/regression tests; delete tests exclusive to retired promises. No substitute Gate, authority, scheduler, role workflow, semantic ledger or ROI theorem.
