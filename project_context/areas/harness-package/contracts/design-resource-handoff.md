# Design Resource Handoff Adapter Contract

## Purpose And Boundary

One shared, conditional design purpose of both development workflows is that Agent implementation, acceptance and testing fully conform to every material UI/UX Fact selected design resources explicitly express within their declared scope and conditions. For a formal selected Web/App handoff, authoring first derives a complete material Expected Fact Universe from requirements, product semantics, the adopted design system and target environments. The atomic identity is one `subject × target × condition × variation × property` Fact Cell—not a Product Control, page, screenshot, broad dimension row or provider summary. Any addressable Surface/region/overlay/system UI, component family and instance, Control, Anatomy Part/slot, primitive, text, icon, media, asset or typed relation remains independently queryable. Long-Task is the stronger machine-enforced carrier; it is not a second copy or the sole owner of this purpose.

This does not authorize inference from silence. A static frame does not imply an unshown interaction, and the workflow cannot prove that the user never omitted a requirement. “Observable” is relative to the acquired immutable format plus a named inspector/project oracle whose supported extraction and verification capabilities are an explicit trusted-computing boundary. An unexpressed fact must be added to Source or explicitly classified; an expressed but unreadable, unsupported or unprovable fact remains `decision_required`/`unavailable` and blocks fidelity work.

The causal chain keeps three authority owners and one separate non-authoritative implementation-feasibility input:

1. **Canonical resources** are the sole exact-value owner for code-expressible layout, visual, content, control, state, interaction, motion, adaptation/input, accessibility and asset values.
2. **Frozen Inspector manifest plus `design-resource-handoff-v1`** expose the exact Fact universe without duplicate ownership. The canonical per-target manifest is the sole complete Fact/Census/proof index. A new handoff uses the same shipped V1 marker with `representation: manifest_backed` and carries only residual Source/scope/resource/target/closure/coverage/proposal binding; preflight hydrates the omitted collections directly from the immutable manifest snapshot. Older embedded V1 input remains readable but is not the authoring default. Neither representation retypes CSS as a second value source.
3. **Context, Contract and Checks** force every Fact and required proof onto the production owner; mutually exclusive **default Contract Conformance** or **Long-Task Final Gate** rejects current-candidate drift with attributable per-Fact results.
4. **`design-resource-implementation-feasibility-v1` Source inputs** record current repository substrate observations and design-family realization candidates or blockers. They carry no exact design value, do not select a production owner or strategy and cannot prove production conformance.

Open Design has demonstrated source-rich output (`index.html`, component/design specifications, tokens and asset manifests), but capability is not a per-run invariant. `design-resource-authoring` must derive the authoring obligation universe before provider execution, pass the adopted design-system ID through MCP, explicitly commission canonical implementation source plus the Fact manifest, retrieve/freeze every dependency and iterate until:

```text
Expected Fact Universe
  = Canonical Resource Facts
  = Handoff Indexed Facts
```

The adapter connects upstream authoring to both development workflows. It creates no provider-specific schema, Design Authority, plan, registry, Claim kind, Gate, acceptance lifecycle or second source of truth.

## One Shared Adapter And Manifest-Backed Target Handoffs

- Exploration and unselected previews need no handoff or validator.
- A newly authored selected handoff is one project-native Markdown Source file per target. It has readable target-attributed Source Items and exactly one fenced `design-resource-handoff-v1` block with `representation: manifest_backed`. The YAML contains only residual scope/provenance, resource identities, one target/profile, resource-fact closure, coverage and proposal binding. Inspector/Census, axes/exclusions, conditions, subjects/variations, properties/lineage, Fact Cells/Facts, evidence/proofs, Oracles/environments, assets and blockers occur only in the target's canonical manifest.
- V1 and opted-in V2 handoffs carry a separate normalized `technical_feasibility_inputs` index. Each entry binds one target to a repository-relative file, media type and current SHA-256. The indexed files are excluded from canonical `resources`, `target.resource_refs`, dependency refs, Fact/rule manifests, `resource_fact_closure`, coverage and runtime canonical closure; therefore the exact design-resource equality is unchanged.
- Authoring freezes the explicit canonical manifest path set before draft generation: exact target/scope membership, manifest file SHA-256 and every declared collection count/identity digest. It also declares an actual UTF-8 handoff ceiling. Shared multi-target meaning is atomized into uniquely keyed target-attributed Source facts without weakening its predicate or provenance; a semantic target is never divided.
- `ty-context design-resource bundle <draft-dir> <new-output-dir> --manifest <facts.json> [...] --max-handoff-bytes <bytes>` is the DSA publication path. It requires manifest-backed one-target drafts, validates the complete explicit manifest/target set, checks actual descriptor bytes before YAML decode, preflights one target at a time from one resource snapshot, preserves exact manifest path/SHA and generation count/digest identity, and atomically renames one same-volume command-owned temporary directory to the previously nonexistent final directory only after every target passes.
- Bundle failure removes only its temporary directory; drafts and existing/adopted handoffs are never overwritten, split or rewritten. The byte check is defense against malformed generation or later mutation, not a post-hoc split strategy. If truthful residual data cannot meet the chosen ceiling, the ceiling is incompatible and publication fails closed.
- `ty-context design-resource preflight <handoff.md>` remains the shared one-file adapter and the read-compatibility path for older embedded V1. For manifest-backed input it parses the small YAML once, reads each declared resource once into one verified snapshot, hydrates manifest-owned collections by reference, then runs the same full semantic, locator, dependency, universe and projection validators used by embedded input.
- Within one scope key, repeated residual provenance/proposal and shared resource/catalog rows must retain canonical identity. File-size, parser, model-output or memory pressure never authorizes pruning, sampling, truncation, coarser Facts, implicit defaults or broader N/A/exclusions.
- Immutable repository resources plus the handoff remain ordinary Source/verifier inputs. The editable upstream owner/locator/update route is recorded separately.
- No persisted aggregate registry is required. Bundle results are diagnostic navigation, not Authority. Default work reruns preflight and exact target-set closure. Long-Task consumes normalized handoffs sequentially and retains only compact target, residual shared-row, resource-path/closure and Source-item indexes; the existing Contract target set rejects missing, extra or duplicate targets. This changes no Contract, Authority, Outcome or Final Gate semantics.
- The shared Selected-Design Conformance Obligation conserves exact Fact Cell, Fact, property-required proof, Source-item, acceptance-blocker, target, condition, variation and property sets into one downstream carrier. Shared input semantics do not imply running both carriers.
- No fixed directory, live provider, artifact count, one-file-per-Control/Fact rule or screenshot Cartesian product is required. “Smallest sufficient resource set” may reduce files, never Fact granularity.

## Implementation Source Profile

Every target declares one `source_profile`:

- `implementation_web`: canonical HTML/XHTML entry, all dependencies, one Fact manifest and `acquisition: complete`;
- `implementation_app`: a canonical machine-readable code/spec entry, all dependencies, one Fact manifest and `acquisition: complete`;
- `reference`: bounded non-Web/non-code resource input; it is not forced into HTML.

The canonical entry plus `dependency_resource_refs` must exactly equal the target's resource set, and `fact_manifest_resource_ref` is a supporting JSON dependency distinct from the entry. Every resource has an exact repository path, media type and SHA-256. Preflight discovers local source imports/loads, HTML/CSS/JS/SVG references, workers, tokens, fonts, images and media and rejects anything outside the frozen set. A PNG may be a derived visual baseline, but cannot be the sole implementation source for state, interaction, motion, adaptation or accessibility.

Before authoring may emit `ready`, the frozen Inspector completely enumerates the canonical entry/dependencies and a Census binds every material resource/node/declaration/token/asset/relation/custom property/variant/state/interaction/dynamic population to exact Fact/Fact Cell identities or source/basis-backed `non_material`. It exercises every property-required verification method under the claimed conditions and cross-checks repeated values across source/spec/tokens/assets. A mismatch is refined or remains `decision_required`/`unavailable` with a blocker. The checked hashes make source QA stale when bytes change; preflight is not production conformance and does not pretend to be a universal semantic oracle.

## Implementation Feasibility Input

`design-resource-implementation-feasibility-v1` is ordinary Source derived from current repository technical Source before formal generation. It names exactly one target and one `native_substrate`, `mapped_substrate` or `reference` mode. It contains strict source records with repository-relative paths, media types, SHA-256 identities, bounded locators and roles; one current file may expose several distinct locators only under the same media/digest identity. It also contains substrate observations for platform, framework/runtime, UI system, token/theming adapter and component/route owner roots; the exact target-condition partition; component-family cells; realizations; and blockers. An observation has exactly one `observed`, `not_applicable`, `decision_required` or `unavailable` disposition: only `observed` carries an observed value and it carries no reason, while every non-observed disposition carries a concrete reason and no value.

For every material canonical `component_family` subject and every applicable declared target-condition region, the input contains exactly one family cell. Its Fact refs are exactly the complete matching V1 Fact set or intersecting V2 Rule set for that family and region. Every cell has one or more Source-backed feasible realizations or explicit blocker refs, never neither. A realization may contain multiple ordered `reuse_existing`, `compose_existing`, `extend_shared_component`, `theme_with_tokens` or bounded custom-shared-component steps; multiple primitive refs; supported customization surfaces; role-bearing feasibility/capability basis refs; observed risks; and multiple owner candidates. An owner candidate is either a currently existing path, or a planned logical owner with explicit authorization Source. `planned` describes existence only. `required_realization` is empty unless an independent current technical Authority Source explicitly selects the exact realization and is cited; neither DRA nor this input may create that choice. The strict model contains no exact visual-value carrier and rejects visual-value syntax in its free technical prose.

V1 condition coverage uses exact explicit condition sets. Symbolic V2 uses the existing restricted predicate grammar and reachable-domain validation so feasibility regions are reachable, mutually exclusive and exhaustive without expanding the Fact/Rule universe. Family and design-fact refs must resolve to the matching target's canonical V1 Facts or V2 Rules. `native_substrate` means only that the design-side component model corresponds to an observed real substrate. `mapped_substrate` means an independent design carrier has complete candidate/blocker mapping. `reference` makes no complete technical-feasibility or formal implementation-handoff claim and may omit this input.

New bundled `implementation_web` and `implementation_app` handoffs require exactly one target-matching feasibility input. For direct preflight compatibility, a legacy V1 or V2 handoff without the field normalizes to `[]`, remains readable under its historical design-resource semantics and reports `technical feasibility not declared`; it gains no implementation-feasibility capability. This compatibility limitation does not weaken canonical resource preflight.

## Canonical V1 Meaning

The frozen `design-resource-observable-fact-manifest-v1` plus the normalized same-V1 residual adapter record:

- scope/provenance/resources/targets/proposal plus exact immutable paths, media types, SHA-256, editable upstream and verified Open Design design-system binding;
- Inspector trust/identity/version/digest, declared capabilities, entry/input paths and digests, `complete_enumeration`, fully enumerated dynamic discovery and an addressable Census with exact Source/basis/rationale;
- design-system snapshot and effective-value lineage across base/alias/semantic/component tokens, platform/mode/state/instance/slot overrides, direct values and resolved conflicts;
- all 33 standard condition axes plus custom axes. Viewport, density, Safe Area and text scale use stable keys with exact width/height/unit, pixel ratio, four insets and multiplier; one key cannot mean two profiles;
- exact applicable target-condition combinations and source/basis-backed exclusions;
- stable subject hierarchy across Surface/flow/region/overlay/system UI/component family and instance/Control/Anatomy Part/slot/primitive/text/icon/media/asset/relation, including parent, instance/family/override/slot, portal, conditional/lazy/virtualized presence and population identity;
- per-subject `variant`, `state`, `interaction_phase`, `presence_phase`, `instance_case` axes, exact combinations and exclusions;
- the standard atomic property catalog plus justified custom properties. Each property carries family, eight-dimension roll-up, typed value kind, Inspector capabilities, Census refs and non-empty required verification methods;
- one explicit Fact Cell for every applicable `subject × target × condition × variation × property` identity. Each cell is `covered`, source/basis-backed `not_applicable`/`excluded_by_scope`, or blocking `decision_required`/`unavailable`;
- one Fact per covered cell with atomic identity, `subject|full_target` scope, `plain|protected` sensitivity, value kind, canonical located digest, evidence, marked Source and value lineage;
- separate proof obligations for every Fact × property-required method. Each freezes method-compatible evidence; comparator; exact/tolerance mode; parameter, tolerance and optional narrow-mask located digests; Oracle trust/identity/version/digest/capabilities; and render-environment identity/definition;
- asset bindings across immutable resource, asset/consumer subjects, targets/conditions and Facts;
- generation closure requiring `complete_explicit`, forbidden sampling/truncation, contiguous chunks and exact count/identity digest for every Inspector/Census/axis/condition/subject/variation/property/lineage/Fact/evidence/proof/Oracle/environment/asset/blocker collection;
- exactly one `resource_fact_closure` per resource and exact roll-up `coverage` set equality across subjects, targets, conditions, variations, properties, Fact Cells, Facts, proofs, evidence, Source and methods.

Supported value/evidence locators are bounded and locally resolved: HTML selector/inner HTML/attribute, Markdown anchor, JSON Pointer, CSS selector/custom property/declaration, JavaScript export, SVG selector/inner XML/attribute and whole resource. Unsupported syntax or prose placeholders fail; critical values cannot live only in a bitmap, preview or natural-language summary. Exact bytes/values remain in canonical resources. Handoff/Contract retain locator/digest and comparison identity, not a copied style/value authority.

The eight dimensions—`surface_flow`, `visual_content`, `component_control`, `state_interaction`, `motion`, `adaptation_input`, `accessibility`, `assets`—are roll-ups only. A label such as `all-21-state-catalog`, one default page, representative viewport, pairwise sample or broad visual fact cannot impersonate atomic axes/cells. Continuous viewport/text-pressure/motion behavior also needs exact breakpoint/range/interpolation/reflow/timeline rules.

An `exact_target` asserts complete visible target fidelity under every declared condition. Each condition therefore has at least one `full_target` `layout_geometry` Fact and one `full_target` `visual_pixel` Fact backed by exact-target evidence. If complete layout/pixel extraction and comparison are unavailable, the resource is a partial `constraint` or remains unresolved. Pixel proof cannot substitute for state/interaction, motion, responsive/input, accessibility, system, haptic/sound or asset methods.

## Opt-In Symbolic UI V2

UI symbolic V2 is explicit opt-in; V1 remains the default. Legacy embedded V1 and manifest-backed V1 retain their existing parser, normalized denotation and downstream evidence contract. An opted-in target declares `design-resource-handoff-v2`, `representation: symbolic_rules_v2` and one `design-resource-observable-rule-manifest-v2`; absence of that discriminator is V1. One Contract may bind V1 and V2 targets together, but each target keeps representation-specific expectations and current evidence with no cross-substitution.

V1/V2 equivalence is extensional rather than physical. For every stable subject or typed relation, target, reachable condition/variation assignment, applicable atomic package/custom property and static/dynamic population plus exact quantifier, the two representations must denote the same disposition, located expected value/type/provenance/sensitivity/lineage and complete required-method proof meaning. Proof meaning includes method, proof surface, furthest independently failing observation boundary, comparator/parameters/tolerance/mask, Oracle, environment, protected-value policy and completion effect. V2 need not preserve the identity, ordering or one-row-per-cell storage of V1 ground Fact Cells.

The first Rule version accepts only a constant canonical-resource located expected value over a restricted package-owned predicate grammar: enum equality/membership, bounded integer ranges and `all`/`any`/`not`. One manifest-level compilation session owns the domain-theory axis partition, predicate/Boolean memoization, decision-DAG hash-consing and subtree sharing without ground expansion. Manifest indexes provide constant-time subject/property/tuple/profile/Rule lookup; no point query or tuple validator scans the complete Rule/disposition arrays. Effective Rule/disposition regions must be reachable, mutually exclusive and exactly cover the reachable universe. Complexity fuses bound predicate depth, input nodes, DAG nodes, partition edges and canonical bytes; theoretical ground cardinality is an overflow-safe diagnostic only.

Applicability begins with the complete package-owned atomic property catalog plus validated custom properties. Legacy manifests remain read-compatible through physical remainder partitions. A compact manifest instead carries package profile references as a storage projection, but the package—not the manifest author—derives each subject's required standard property set from the frozen Inspector Census, subject kind, presence/population/relation classification and the versioned subject-capability algebra. The referenced profile union must equal that derived set for every bound subject; it cannot narrow the standard universe. The frozen Inspector's `custom_property` Census then closes the exact nonstandard set and unique instance exceptions may change one subject-property disposition only with a basis resolving to the package policy, a validated Inspector Census output or a current non-interference proof artifact. Therefore `package-derived standard applicability + Inspector custom-property closure + explicit validated exceptions = effective applicability`. This removes the physical subject × complete-property N/A matrix while every logical subject-property point still has exactly one disposition. A specified Rule needs matching subject/relation and property Census entries, required Inspector capabilities and closed resource inputs; missing derived-profile equality, unresolved basis authority, ambiguous exceptions, custom-property authority or reachable coverage blocks. Rule identity, semantic proof-obligation identity and non-interference certificate identity are separate typed namespaces. Every property-required method receives its own exact Rule-region obligation.

V2 returns its existing `status: ready` only after closure. `decision_required`, `unavailable`, `blocking` and any acceptance blocker continue through the existing fail-closed exception path; they do not create a public readiness state machine. Proof admission reuses V1 method/dimension, comparator/method, Oracle trust/digest/capability, environment/resource, exact/tolerance/mask and protected-value policy. For an exact target, the union of `full_target` `layout_geometry` proof regions and the independently computed union of `full_target` `visual_pixel` proof regions must each equal the complete reachable visible/render domain.

One set-valued certificate may cover multiple Rule identities and omitted axes; it directly carries those exact sets and physical Rule × axis dependency edges are forbidden. Admission separately reports semantic-obligation count, certificate-obligation count, exact covered omitted-axis sets/counts, canonical DAG nodes/edges/bytes and theoretical cardinality. A declaration, provider `complete` flag, author-supplied graph/predicate, `oracle_ref`, `recomputed` flag, passed verdict or self-consistent dependency list proves no independence. Every omitted axis requires both Source-side and production-side proof by exactly one trusted method: complete static dependency closure over frozen closed-world inputs, exact symbolic equivalence in the restricted decidable IR, or true exhaustive equivalence over a finite complete domain. Dynamic loading, reflection, unfrozen implicit CSS/DOM or other dependencies, external devices, representative points and sampling block; the axis must otherwise re-enter the explicit Rule. Dispositions and population exclusions remain explicit when they omit any axis. Canonical work never samples, reduces granularity or expands then deduplicates.

Every proof method requires a digest-identified `frozen_executable` Oracle with the exact `symbolic_noninterference.<side>.<method>` capability. Each side also names one immutable supporting proof artifact. The artifact and proof binding include the Oracle implementation-closure digest/version, exact capability, resolved environment digest, every Inspector input path/declared/current digest, side-specific current Source-manifest or production-target digest, exact Rule/certificate scope, omitted-axis set, derived dependency-DAG/IR/equivalence result digest, artifact path/digest and a nullable attributable failure witness. The package Oracle digest is recomputed from the actual installed executable module closure, not from author metadata or a prose algorithm label. Package preflight deterministically reruns that versioned verifier over the current frozen resources and Source/production snapshot, requires `recomputed Oracle output = referenced artifact bytes = proof binding/cache`, and rejects any failed result. The artifact is excluded from the semantic input closure.

For Source-side proof, current meaning comes only from the package-owned canonical restricted Source IR found in the complete current Inspector input set. That immutable, non-executable IR binds the exact current target and certificate/Rule scope and supplies the Source expression that the package parser compiles; submitted dependency nodes, Rule roots, side predicates, axis-erased predicates, evaluation claims and passed flags are cache fields and never Oracle inputs. The static method derives its dependency DAG from that current IR, the restricted-equivalence method derives and canonicalizes both current Source and axis-erased predicates, and the finite method evaluates the package-derived Source denotation over every assignment in the complete current axis domains within its fixed capacity fuse. Missing, duplicate, noncanonical, stale or scope-mismatched IR, executable Source, CSS cascade/implicit DOM semantics, template/runtime conditionals, dynamic load/fetch/import, reflection, computed access, external device/runtime dependencies or an unfrozen extension all return an attributable unsupported/counterexample witness and block `ready`; text absence, representative points and sampling never prove independence. A static proof is not a declared axis list and cannot be manufactured from `Rule.referenced_axis_refs`.

The production Oracle retains its narrower package-defined decidable subset: one non-executable static HTML entry plus inert JSON dependencies, including the canonical Source IR only as inert data. Script/style/template/event/external-load/interactive or other unsupported markup, executable/style/vector media, implicit CSS/DOM, dynamic/reflected access and external devices all block. The two complete proof digests participate in certificate identity and, when present, in the existing Contract certificate expectation/current result. Preflight, Long-Task source Compile and the sole Final Gate source recompile invoke this same current-input derivation and artifact comparison; comparing a proof-object digest alone is never sufficient. Extraction outside the admitted restricted representations remains an explicit TCB boundary rather than an inferred success.

V1 capacity admission uses resource stat plus a bounded prefix generation header before full read, JSON parse, hydration or Cartesian validation. Thresholds are repository-measured, diagnostics include measured value/limit and explicit V2 guidance, and no row is truncated. Over-capacity V1 input fails; it does not silently opt into V2.

Long-Task V2 targets project `symbolic_method_bindings` with typed per-Rule/method-region current results and one separately typed `design_symbolic_certificate` binding/result. When a certificate omits axes, its Source and production proof digests are exact expectation/result fields; the existing source-recompiled Final Gate evaluates them alongside ordinary V1 `fact_expectations`/`fact_results` on one current snapshot. No certificate replaces semantic proof, no historical result is reused and no second Authority, Gate, receipt, registry or completion state is introduced.

Purpose-fulfillment efficiency non-degradation is a package mechanism-change admission property, not an AcceptedDeliveryTerminal condition. It requires a named workload, metric, baseline or budget, environment, comparator and tolerance whenever runtime efficiency is claimed. The deterministic structural fixture fixes 639 subjects, 217 package properties, 53 axes and 5,245 variations, asserts all 138,663 logical subject-property dispositions, and measures actual authoring/preflight wall time, manifest bytes and RSS while forbidding 137,385 physical N/A rows and Rule × omitted-axis edges. It creates no delivery deadline or fixed execution flow. Non-UI symbolic admission remains out of scope; machine-observer and verifier/runner trust-boundary closure is mandatory rather than deferred Provider/P0 work. The observer boundary enters only through its separate evidence-backed admission and owning-Context/Authority decision; the shared symbolic engine alone does not import UI policy into another domain.

## Fail-Closed Validation

Preflight rejects unknown fields; duplicate/unknown/aggregate keys; unsafe paths; missing/stale bytes; digest or source-profile/dependency drift; incomplete/non-frozen Inspector inputs; missing Census semantic owners; absent standard axes/values/properties/methods; condition-profile ambiguity; incomplete Cartesian condition/variation/Fact Cell universes; sampling/truncation/count/digest drift; invalid N/A/exclusion basis; subject hierarchy/presence/population/relation errors; invalid value kind or unresolved locator; design-system lineage/conflict drift; missing/extra/duplicate Facts or Fact × method proofs; incompatible evidence/comparator/Oracle; environment/mask/tolerance outside canonical resources; asset binding drift; manifest-backed target-count or manifest identity drift; embedded manifest↔handoff mismatch; material resources disguised as supporting-only; exact targets without full-target layout/pixel Facts; cross-target/condition substitution; `decision_required`/`unavailable`; and any acceptance blocker. For a declared feasibility input it additionally rejects unsafe or stale Source records; target mismatch; technical/canonical resource mixing; unknown or duplicate identities; unresolvable family/Fact/Rule/condition refs; incomplete or overlapping family-condition coverage; omission of a transitive family descendant Fact/Rule; a cell with neither candidate nor blocker; unsupported strategy order or customization surface; an existing owner path that does not exist; owner-root observations that are identifiers, missing, outside the repository, files or links; unresolved formal-target observations without an affected Source-backed blocker; a planned owner, required realization or blocker without exactly one matching current marked-Source-Item projection; stale item text digest; wrong item kind; and exact visual values carried in any feasibility free text.

Preflight proves declared-universe completeness, addressability and immutable integrity relative to the named Inspector/Oracle TCB, plus only the declared technical-input integrity, reference closure and candidate-or-blocker coverage. Its compatible JSON `status: ready` means only that this validator completed successfully; human output says `preflight valid`, reports input/cell/blocker counts and explicitly says production conformance was not evaluated. Bundle publication likewise publishes an ordinary Source bundle and never claims production readiness. A structurally valid limitation or blocker remains an exit-zero honest input result, while structural or closure failure remains nonzero; no warning/readiness state machine is added. Preflight cannot prove the user supplied every real requirement, that an arbitrary Inspector is semantically sound, that a feasibility candidate is the best production choice or that production conforms. Project mutation/current-snapshot checks must still demonstrate each implementation method and Fact fails when its production carrier is wrong.

## Default Workflow Consumption

The default Workflow:

1. reruns preflight and opens every affected exact/constraint resource plus its current matching feasibility Source when declared;
2. reconciles stable subject/target/condition/variation/property keys through owning Surface/Screen/Control Context and `DESIGN.md` without rebuilding the handoff's complete Fact universe as a task ledger;
3. identifies the affected target conditions, material Source Items, blockers, candidate owner/strategy set and cold-start real-entry journeys, widening when shared design or code ownership is uncertain;
4. uses Architecture Deliberation—not DRA or the feasibility input—to select the actual production owner and realization under current repository architecture and records no binding ledger;
5. selects project-native page, interaction, visual, accessibility, runtime or other checks in proportion to the actual fidelity claim and risk, and reruns affected checks after the last relevant candidate/input change;
6. on the final current candidate reports which declared conditions were implemented and verified, which remain unverified because no reliable project observation exists, and which are blocked by conflict, missing authority or external confirmation, then performs Contract Conformance plus Context drift checking.

Resource presence, hash success, provider success, aggregate pass, screenshot or detached route cannot substitute for production checks. Unsupported, unreadable, stale or conflicting selected authority blocks the affected claim; an unchecked condition cannot be folded into a complete-design claim. The default route creates no per-Fact result rows, frozen comparator/Oracle/environment graph, exact-set equality, persisted map, Claim set, readiness state or Gate. When every declared Fact and method requires machine-traceable current results, explicitly select Long-Task.

## Long-Task Consumption

Long-Task Preflight/Compile requires each Contract `design_target` to match exactly one V1 or V2 target across all declared handoff files by key, representation, interpretation, conditions and complete handoff/resource file set. Every handoff, canonical resource/manifest and declared feasibility file is real `task.source_paths` Source; the owning handoff and every target entry/dependency are Check `verification_inputs`. The adapter preflights, binds and releases one normalized target handoff at a time while retaining only compact identity/digest/error indexes. Actual choices use only existing `outcome.technical.bindings`, `surface_bindings.route_binding_ref` and `component_binding_refs`. For each candidate-bearing feasibility cell, Long-Task derives the allowed realizations which match current component bindings: an existing candidate matches an existing file target or carrier pattern, and a planned candidate matches a planned binding key/target plus its exact Source authorization. A required realization must be the sole match; otherwise zero matches fail missing, multiple matches fail ambiguous and one match uniquely derives the current selection. A blocker-only cell has no realization to derive and instead proceeds directly to the exact blocker completion boundary below. Every referenced component binding must still be consumed by at least one current-target candidate-bearing cell, existing component owners/bindings must remain inside observed component roots and the route binding must remain inside observed route roots. Shared bindings remain valid only where each consuming cell explicitly allows them. Nothing persists the derived selection.

Every planned-owner authorization, required realization and blocker must resolve to its exact `path#source-item-key` Source Claim; path-only or same-file unrelated Claims are invalid, the Source file must be in `task.source_paths`, and current item text must equal the feasibility digest. Required-realization authority enters the current Outcome Claims or a Global Constraint; selected planned-owner authorization enters the current Contract. A feasibility blocker remains blocking even when a candidate exists: its exact marked item must map either to `decision_required` or to an existing target-blocking External Confirmation whose impacted Claims include the current target. The existing Final Gate therefore cannot return `machine_accepted` while that confirmation remains pending. The feasibility model creates no Contract field, binding kind, Claim kind or Gate. Deterministic diagnostic precedence remains Source-order preflight, duplicate/index errors, Contract-target order, then unbound targets, with unchanged one Contract/Authority/Final Gate semantics.

Covered Source Items map through `source_claims` into the target's single-Claim root conformance Assertion and, where the Source meaning is method-specific, the corresponding single-Claim method Assertion. For each verification method, the union of those two Assertions must cover every Claim mapped from the Source Items referenced by that method's Facts or Rules; a Claim absent from both fails closed. The exact proof-method set maps through `verification_method_bindings` to distinct positive Assertions in the same target Check, so this set coverage neither permits a multi-Claim Assertion nor collapses independently attributable method proof into root conformance. Every method × condition cell carries exact `fact_refs` plus canonical `fact_expectations`: subject/variation/property, sensitivity, expected located digest, comparator/parameters/tolerance/mask, Oracle and environment. These references preserve full value granularity without copying CSS. Cell unions close all Fact × required-method obligations and the complete target Fact set.

Current `design_method` evidence repeats those Fact refs and supplies exactly one `fact_results` row per Fact: subject/variation/property; actual observation and actual environment path/hash/typed locator/value hash; expected and comparison artifacts/authority; explicit verdict; Oracle and environment. Runtime rejects missing/extra/duplicate rows, identity/authority/sensitivity/environment drift, unexpected/missing redaction, reused indistinguishable observations and any failed verdict. Runtime `design_conformance` records accept either the root Assertion or explicit method bindings, so method failures remain independently attributable.

For an opted-in V2 target, ground `verification_method_bindings` remain empty and `symbolic_method_bindings` project every Rule × required-method obligation with canonical region digest, expected locator, comparator, Oracle/environment and protection semantics. Typed `design_method` evidence carries `fact_model: symbolic_rules_v2` and one exact result per Rule obligation. A distinct certificate Assertion/capability carries fresh recomputed certificate results and the frozen obligation/coverage/DAG/byte metrics. V1 records cannot satisfy V2 bindings, V2 records cannot satisfy V1 bindings and neither can substitute for root design conformance.

Each handoff acceptance blocker binds the same Source Items and verification methods in `surface_binding.acceptance_blockers`. A machine blocker must reference the corresponding target-local Claims; an external blocker must use a target-blocking External Confirmation whose impact includes those Claims. A matching key with unrelated proof is invalid.

Existing Controls/`surface_bindings`, production owners/root journey, Evidence Kernel, Counterfactual sensitivity, Authority Revision and source-recompiled one-snapshot Final Gate remain the only acceptance/lifecycle owners. Selected-target Fact expectations are protected Authority; any change after lock revises Authority and invalidates affected evidence.

Long-Task is therefore the machine carrier of the same shared obligation and never runs the default task-local selected-design closure before or after Final Gate.

## Provider Selection Background

The default remains Open Design source-rich output plus the provider-neutral residual handoff and existing Final Gate.

- **Figma** is valuable when an existing Figma authority/team needs native Components/Variables/Variants, shared libraries, Dev Mode or Code Connect. It also introduces paid-seat/plan and MCP quota/authentication boundaries plus a second-representation synchronization cost, so it is optional rather than a default conversion target. See [pricing](https://www.figma.com/pricing/) and [MCP access/rate limits](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/).
- **Penpot** is a credible open/self-hosted collaborative platform with an open ZIP/JSON format and MCP. It is appropriate when self-hosted multi-user design infrastructure is itself required; otherwise service/plugin/open-file/deployment/backup operations and a second representation do not close a distinct workflow-enforcement gap. See [file format](https://help.penpot.app/technical-guide/developer/data-model/penpot-file-format/), [MCP](https://help.penpot.app/mcp/) and [self-hosting](https://penpot.app/pricing/self-host).
- **OpenPencil** is a useful MIT local static-design sidecar with CLI/MCP and HTML/CSS conversion. Its documented prototype flow/trigger/action/overlay/Smart Animate gaps prevent it from being the sole eight-dimension interaction/motion source today. See its [repository](https://github.com/open-pencil/open-pencil) and [compatibility roadmap](https://openpencil.dev/development/roadmap).

Any of the three may become an optional upstream adapter when the project has that real collaboration/authority need. Converting an already complete Open Design source into another format does not create missing information and never replaces handoff/Contract enforcement.
