# Package-Managed Surface Contract

Product Surface Contract guidance is package-managed workflow support only. It must not generate project semantics, plan artifacts, lifecycle state or campaigns; business surface responsibility remains project-owned Context using existing roles.

## Role

This contract defines source-only, managed, packaged and human-facing surfaces for the Harness.

## Surface Ownership

- `.codex/ty-context-managed/**` is source-workspace managed source for portable/default guidance, Context templates, profile metadata and package-managed Skills. The executable Long-Task Hook entry is package-owned compiled code.
- Managed Context templates include cross-surface `product-surface-contract.md` and optional on-demand `screen-contract.md`. They teach ownership/structure only and never generate consumer product facts.
- `packages/ty-context/assets/**` is packaged canonical output produced by source mappings.
- `.codex/skills/**` exposes generated/default Skills. The base set includes `design-system-authoring` and `design-resource-authoring`; `long-task` owns only `long-task-workflow`. Retired compatibility pointers and alternate Long-Task Skills are not installed. Enabled package-owned copies are sync-overwritten.
- The Long-Task main `SKILL.md` is the compact objective, boundary, activity router and lifecycle summary. Its existing one-level Source-authoring, Contract-authoring, Evidence-design and Authority-lifecycle references are the sole detailed instruction owners; atomic rule blocks are not duplicated back into the main Skill or another Skill/reference/stage. Managed source, installed workspace and package-asset copies remain byte-identical.
- `.codex/ty-context-managed/agents/long-task-implementation.toml` is the sole machine-readable source for the optional Codex-native rolling implementation profile, including its fixed model and reasoning effort; `packages/ty-context/assets/agents/**` is its exact package copy and `.codex/agents/long-task-implementation.toml` is the consumer install path only when the resolved harness root is exactly `.codex`. The profile sets child-local `[agents].enabled = false`, never sets `service_tier`, and is static, stateless, non-Authority and usable only after the parent checkpoint. On a supporting host it therefore does not override the parent Goal's current Fast/Standard tier, but Tiny Context neither owns nor independently observes the effective child tier and reports it unverified when the host exposes no evidence. A host whose custom-agent schema rejects the required leaf field treats the profile as unavailable and uses parent execution; package compatibility never deletes the boundary or substitutes a generic child. It is not a Skill, model router, scheduler, runtime or acceptance surface.
- `.codex/skills/authoring/**` is source-workspace-only and never packaged.
- `README.md`, `README.zh-CN.md`, `packages/ty-context/README.md`, npm metadata and release docs are human-facing public surfaces and must match behavior.
- `PROJECT_SPEC.md` is the full source-workspace workflow design specification, not a consumer asset.
- `project_context/**` is source-workspace durable fact authority and is not copied wholesale to consumers.

## Profile And Consumer Boundary

- `core-portable` plus `workflow-default` are installed by default.
- `long-task` is explicit. Enabling it installs Long-Task Workflow, package-owned lifecycle Hooks and templates; for an exact `.codex` harness root it may also install the optional fixed Codex implementation profile. One pure TOML validator requires the exact marker/name, non-empty description/instructions/model/reasoning effort and child-local multi-agent disable while rejecting extra routing/registry/runtime or dynamic-value fields; it returns the current static model values from TOML rather than duplicating them in validator code. Missing/invalid package assets and non-regular, symlinked or no-marker user destinations are skipped without changing Long-Task acceptance. The exact marker establishes package ownership for a repository-contained regular destination, so enable/sync can refresh the former managed schema and disable can remove it; first-lock bootstrap is stricter and admits only the fully valid current profile that is byte-identical to the valid package asset. Every existing parent is inspected without following links, external link targets are never read, and siblings receive no package protection.
- Managed profile publication uses a unique same-directory file created exclusively, fully written and atomically renamed with cleanup on failure. A write/rename failure leaves the prior destination intact; stale temp siblings do not collide. An invalid or missing package asset never deletes a valid consumer profile, and ordinary non-Codex harness roots never create `.codex/agents/**`.
- Hook configuration publication inspects `.codex` and `.codex/hooks.json` with non-following `lstat`, rejects symlink/junction/non-directory parents and non-regular or invalid-JSON targets, preserves non-package groups/entries/metadata, snapshots the current target, creates one exclusive same-directory temporary file, rechecks the target before atomic rename and fails on concurrent change. Failure keeps the prior target and cleans only its own temporary file. Legacy local-Hook deletion applies the same parent no-link boundary. A first install or package-owned Hook update emits the non-blocking `/hooks` review notice; the host/user owns trust, changes may require re-review, and Tiny Context cannot grant, observe, persist or bypass Hook trust.
- Upgrade safely removes the legacy package-owned repository-local Hook, reports unfinished legacy or development-period active state as manual, and never imports historical Progress/Receipts as current authority.
- Retired command names are isolated non-executing CLI tombstones in code, not packaged runtime profiles. They import no retired orchestration, worker, App Server or worktree modules.
- `init`, `sync` and `upgrade` never create, discover, import, activate or abandon a Delivery Contract.
- Consumer CI receives portable project gates only. Maintainer package CI owns Delivery Contract/Long-Task Workflow self-tests, exact-tarball smoke and source drift.

## Source Sync Boundary

- `node packages/ty-context/dist/cli.js package sync-source` copies mapped managed source to package assets.
- `package check-source` verifies exact mapping parity.
- Run build, sync twice, check-source, the enabled-profile workspace sync and relevant consumer/package tests after changing managed guidance, Skills, Hooks, templates, custom-agent profile metadata or source mappings. Each package-managed Skill's managed source, generated `.codex/skills/**` copy and package asset must be byte-identical; the managed/package/installed Codex implementation profile has the same exact parity requirement.
- Public `sync` refreshes enabled package-managed assets only; semantic migration belongs to `upgrade`.

## Generated Skill Boundary

- Package-managed Skills are business-agnostic. Project facts belong in the consumer Context or separate project-local Skills.
- Package-managed AGENTS is the sole automatic runtime projection of the stable Shared Engineering Quality design owned by `PROJECT_SPEC.md` and Context. The content-sensitive `context_development_engineer` adds material architecture/engineering-design judgment when the task substance requires it, while generic implementation/fix/refactor wording and ordinary local work do not activate it merely by themselves; it does not own ordinary implementation. Its on-demand engineering-design reference carries deeper fact/assumption, driver/path-dependence, alternative/counterfactual, minimum-experiment and concrete-boundary reasoning without making every method mandatory. `long-task-workflow` and public docs preserve one visible risk-proportional Architecture Deliberation with triggered quality-attribute assessment, Goal-owned implementation guardrails and one current-candidate Engineering Quality Conformance containing Architecture Conformance. Default Contract Conformance and Long-Task Final Gate are mutually exclusive carriers; the Gate proves only declared falsifiable project-check-bound invariants. Freshness, debt and Context-drift direction stay explicit, with no quality artifact/matrix, field/aspect/Claim kind/risk, second Authority/Gate, state or broad quality Boolean.
- Managed/public modularity guidance describes `check-modularity` as a portable capability-aware heuristic: JS/TS lexical metrics, Python per-function statement/branch metrics and line-only coverage for other included formats; unsupported values are `n/a`, project-native tools remain primary and no architecture or runtime-performance guarantee is claimed. Semantic waiver cleanup belongs to versioned `upgrade`, never ordinary `sync`.
- Package-managed AGENTS, `context_development_engineer`, Context templates and public docs preserve the same monorepo semantics: `project_context/workspaces/<workspace-id>/**` is an optional centralized sparse mirror; every represented Context workspace maps one code root with existing `[[areas]].root/context`, may contain several workspace-local Areas, and unrepresented code workspaces require no empty directory; cross-workspace Areas remain top-level, a small repository-common top-level Area is the normal default, workspace-local Context stays on-demand unless near-universal, and non-monorepo layout is unchanged. Default/manifest/search selection is an expandable minimum rather than read isolation; task-local intended workspaces remain distinct from shared/supporting reads or changes; unresolved sibling ambiguity blocks product edits; and available project-owned changed-path checks run on attributable paths. These surfaces add no workspace schema, automatic topology scan, migration, persisted target state, full-graph default, universal scanner, implicit workspace-local Design Authority or duplicate Long-Task classifier.
- Package-managed AGENTS and public docs preserve only a short route to the canonical Skill's packet-first positive-default and the Workflow Contract's six parent-only/partial-delegation semantics. The main Skill alone owns packet contents, exact spawn attempts and shared-worktree integration; generated/install/package copies stay byte projections. Source/Contract, architecture, security, forbidden-shortcut and irreversible/external-action boundaries remain binding, while implementation order, methods, feedback cadence, concrete packet decomposition and dynamic worker count remain Goal-owned. Harness creates no development phase/method Gate, per-edit mandate, fixed agent count, Outcome-to-Agent mapping, allocator/retry/scheduler/DAG/queue/registry, delegation proof or persistent delegation state; every result converges into the selected verification workspace.
- The optional `long_task_implementation` profile does not change that boundary: it can implement or repair only its bounded parent packet after the checkpoint, cannot revise Source/Contract/Authority/Context or produce Progress/Evidence/Receipt/Final-Gate proof, cannot choose models, spawn/retry/schedule agents, create branches/worktrees or claim acceptance, and is never required by Compile, Verify, Final Gate, Stop or close. Parent execution is the fallback when it is unavailable. The parent owns architecture, Context writeback, integration, current-candidate checks, formal verification, Final Gate, close and native-Goal completion.
- The package-owned `PreToolUse` Hook group matches `^(spawn_agent|Agent)$` and, only with an active binding, denies the call unless the official `tool_input.agent_type` is exactly `long_task_implementation`. Before allowing that exact selector, it freshly reuses the existing no-follow bootstrap-path inspection and requires the installed regular profile to parse and remain byte-identical to the current package asset; missing, invalid, outdated, symlinked, non-regular or otherwise conflicting state denies the spawn and returns execution to the parent. This check proves only that the profile visible immediately before spawn matches the package asset; it is not an atomic or cryptographic proof against a same-user change between Hook completion and the host's later load. Inactive work is unrestricted. The Hook never rewrites input, interprets task name/prompt/model as identity, retries, substitutes or persists capability/delegation state. The exact `SubagentStart` matcher `^long_task_implementation$` remains the worker-boundary injection and consumes only official `agent_type`/`agent_id`. SessionStart/PostCompact recovery and Stop completion semantics remain unchanged; neither Hook output nor a delegated report is workflow authority or acceptance evidence.
- Default role Skills have non-overlapping durable owners: product meaning (`context_product_plan`), page duty/information-action-feedback/interaction topology (`context_surface_contract`), Design Authority/adoption/alignment (`context_uiux_design`) and material architecture/engineering design (`context_development_engineer`). `context_uiux_design` may load one non-authoritative task-analysis reference for material page/flow/control, hierarchy/topology, task-feedback, client adaptation, recovery/state/accessibility or audit judgment; Product/Surface/Screen Source still owns the governing facts and the current Goal owns candidate selection under them. Generic implementation, fix/refactor, agent/delegation or role wording triggers none merely by itself, while materially matching task content may route to the relevant reasoning adapter. Skill activation grants no Context write authority.
- Open Design owns default generation. `design-system-authoring` is explicit-only, feature-detects MCP lifecycle support, uses the official same-daemon fallback when needed and adopts one selected system into canonical project authority without a provider registry. `design-resource-authoring` gates only style-bearing resources, verifies `designSystemId`, commissions the smallest scoped set and reconciles accepted final decisions into the caller-owned initial proposal once. Before page/flow/complex-control generation it consumes the available Product/Surface/Screen/UIUX constraints for target user/context, client/host, page duty, primary task, primary work object and operation-object-feedback loop; missing product meaning stays unresolved rather than being inferred from a feature list. Its Open Design provider reference owns the durable `highest_available_capability + highest_supported_reasoning_effort` policy for formal generation, major revision and critical regeneration: it filters for required tool/visual/context/auth/data eligibility, uses only provider ranking/replacement evidence or one versioned provider-local fallback mapping, rejects name/price/date/list-order guesses, verifies requested versus effective runtime provenance and reports `highest_performance_unverified` rather than silently degrading or claiming an unobservable result. This creates no scheduler, model registry or routing state. Its main Skill stays a compact intent router; the on-demand recovery/writeback reference owns complete Base/Delta replay, non-circular decision authority, current bidirectional audit and the conditional checkpoint/helper route, while exactly one `formal-selected-web-app-handoff.md` owns the full Expected Fact/Census/method/bundle protocol and exploration never loads either high-cost path without its trigger. It never edits other caller-owned Source, Context/`DESIGN.md`, code or Contract and adds no live provider dependency/authority.

## Change Impact Rule

Public behavior changes require a same-semantics sweep across implementation, schema, managed source, package assets, Context, PROJECT_SPEC, English/Chinese README, package README, tests, source sync, quickstart/tarball and release/version surfaces as applicable.

The public README Contract and reusable release fixture are executable examples, not regex documentation. Source sync owns README/package copies and both Skills; exact-tarball smoke and its built-CLI fixture must share the same marked Source/Binding/Counterfactual semantics.

Public package surfaces must be English-complete. Chinese text is additive aligned documentation, never the sole activation path or explanation.
