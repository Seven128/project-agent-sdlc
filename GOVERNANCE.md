# Governance

The project maintainer owns product scope and releases. Tiny Context preserves project-specific facts and one short development contract; its helpers do not govern an agent's task lifecycle or certify product completion.

Changes should preserve user authorization, project requirements and safe file maintenance. Judge verification by actual affected behavior and current results, not mandatory artifacts, source length or generic scores. Schema changes require explicit migration and documented compatibility limits. Scope-changing decisions belong in durable Context.

Use issues and pull requests for proposed changes. Publication and external actions need the applicable maintainer authorization. Historical workflow/benchmark governance is not an active requirement.
